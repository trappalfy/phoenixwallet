# Chrome Web Store submission package

Everything here is submission material — none of it ships inside the extension itself
(`store/` is not part of `dist/`, and `npm run package` zips `dist/` only).

## What's in this folder

- `listing.md` — name, summary, description, category: paste into the dashboard's Store listing tab.
- `permissions.md` — why zero permissions are requested, and the single-purpose description.
- `privacy-policy.md` — the actual policy text. Its live copy is served at
  https://perigeewallet.space/privacy.html; the two are kept in sync by hand, so edit both.
- `screenshots/` — five 1280×800 PNGs of the real popup (Welcome, Recovery phrase, Home, Receive,
  Settings), generated by `scripts/store-screenshots.mjs`.
- `build/` — where `npm run package` writes the submission zip. Gitignored: it is a build output,
  so regenerate it rather than treating it as source.

## Steps to actually submit

1. `npm run build && npm run package` → produces `store/build/perigee-wallet-<version>.zip`.
   Build from a **fully merged** working tree. A zip built on a feature branch shipped stale
   icons once: the recolour lived on a sibling branch, so `dist/` picked up the old PNGs while
   the JS and CSS were current, and nothing in the build output flagged it. `git status` clean
   is not the same as up to date with everything that is meant to be in the release.
2. In the Chrome Web Store developer dashboard: **New item** → upload that zip.
3. Store listing tab: paste from `listing.md`, upload the five images from `screenshots/`.
4. Privacy practices tab: paste from `permissions.md`. This tab wants a **URL** for the privacy
   policy, not pasted text: https://perigeewallet.space/privacy.html (source: `public/privacy.html`
   on the landing site). The mailbox that page lists, privacy@perigeewallet.space, has to actually
   receive mail — a policy contact that bounces is grounds for rejection on its own.
5. **Visibility: set to Unlisted**, not Public — see `docs/phoenix-wallet-PROMPT.md`'s §14 note and the
   earlier discussion: this is a demo wallet with no real wallet functionality, and a public
   "Perigee Wallet" listing risks both store-review rejection under crypto-wallet scrutiny and a
   real user mistaking it for a working wallet. Unlisted still yields a working
   `chromewebstore.google.com/detail/<id>` URL for the landing site's hero button. It is a
   dashboard dropdown, not a rebuild — flip it later if that decision changes.
6. Submit for review. Unlisted items go through the same automated + manual review as Public ones
   (visibility does not relax review), so this can still take the usual review turnaround.
7. Once approved, copy the listing URL back and it goes into `src/content/copy.ts`'s
   `chromeStoreUrl` on the landing site. **Done** — approved and live at
   `chromewebstore.google.com/detail/perigee-wallet/lkhpcjjibfmepfpeodiidmolhigmifah`. Strip the
   `?authuser=` and `?hl=` parameters the dashboard appends before storing it: the first is tied
   to one Google account's session, the second pins every visitor to one language.

## Regenerating screenshots

```bash
npm run build && npx vite preview --port 4180 &
node scripts/store-screenshots.mjs http://localhost:4180
```
